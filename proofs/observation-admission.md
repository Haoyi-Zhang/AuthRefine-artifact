# Source-observation admission

Observation comparison requires the declared fixture set and the values and
types of every compared field. A missing row cannot establish agreement for
that fixture; an integer zero is different from a Boolean false in a recorded
serializer argument.

## Credential boundary

The three recorded credential programs remain unchanged. Their current public
check and replay entry points apply `source_study/observation_evidence.py` to
the complete independently regenerated fixture list. The gate checks unique,
ordered fixture identities, the expected and observed fields, their scalar
types, record transfer and serializer arguments, and recomputes agreement and
totals. The observation key `version` corresponds to the source call keyword
`v`. Source-language Python equality retains its original semantics.

The retained admission review actually reexecutes all 1,260 baseline contexts
through the selected IR bodies with Django ORM and SQLite primitives. All
baseline observations agree with the original retained data. Two private IR
copies change one serializer keyword each: `readonly=False` becomes integer
zero, or version one becomes Boolean true. Each control executes two SELECTs.
The historical collector reports agreement, while the current admission gate
rejects the captured argument's incorrect type. These are validation controls
for this boundary, separate from the full HTTP application study.

```sh
python -B benchmarks/audit_credential_admission.py --mode check
python -B -m unittest discover -s tests -p test_observation_evidence.py -v
```

The first command verifies all three retained modes using the standard library.
The raw observations and actual acquisition metadata are in
`results/credential-admission-review/`. With the Django environment, use
`--mode all --output /fresh/credential-admission` to repeat the actual executions.
SQL and MAC counters are schema-checked and totals are recomputed; the finite
reference predicts the public observations and serializer transfers. Actual
baseline reexecution additionally compares the complete retained result tree.

## Independent source-body observation

The independent observer requires all 480 reads, 448 resume state/input edges,
288 event-access inputs and 16 owner-insertion inputs. Its gate checks the
complete unique identities, typed observations, and every reaching-prefix
observation against the corresponding recorded graph edge. The IR provider's
`mark_as_processed` argument must be Boolean true, matching the separate
CPython primitive contract.

The corrected observer was actually reacquired before its new runtime record
was installed. Its five scientific data files remain byte-identical to the
earlier acquisition. All 1,232 comparisons still agree, and the eight source
controls retain 318 differences across 2,896 executions: 294 preserve the
response/entry decision and 24 change it. The new runtime binds the actual
acquisition and its 32 participating source files.

```sh
python -B -m source_study.verify_source_observer --results results/source-observer
python -B -OO -W error -m source_study.verify_source_observer --results results/source-observer
```

This read-only entry point reconstructs the selected CPython observations,
production comparisons, 52 fixed-binding witness replays, all eight source
controls and the complete summary. It also checks the retained source and
output identities. It executes the explicitly supplied function-body fixtures;
the full Django HTTP and native session studies have their own entry points.

Pretix query/handoff metadata remains a direct-observer field; its paired
claim is the five exported fields described in the paper. Wger compares saved
rows, save-call count and exact request-user identity. These field contracts
are preserved by the stricter admission checks.
